Integration Reliability Kit

ERP·API·파일 연동에서 일부 행이 실패하면 정상 건까지 다시 처리되거나 중복 반영되어 검수와 복구 비용이 커지는 문제

지금 상태
공개 URL에서 샘플 데모 확인 가능부분 실패, 실패 로그, 수정 후 재처리, 중복 방지, 합계와 체크섬을 공개 샘플 데이터로 확인할 수 있습니다. 고객 성과는 아직 검증하지 않았습니다.
단계
코드·테스트·샘플 데모 검증 · 공개 배포 확인
직접 확인

누구를 위해, 어떻게

이 제품을 찾는 사람
엑셀·ERP·외부 API 사이에서 반복 업로드, 정산, 전표 변환을 운영하는 작은 팀
처음부터 신경 쓴 점
실제 고객 데이터나 특정 ERP 접속 정보 없이 복구 구조를 증명해야 하며, 샘플 성능을 고객 성과로 말하지 않습니다.
고른 해결 방법
입력을 정규화·매핑·검증한 뒤 멱등 키로 중복을 막고, 정상 행과 실패 행을 분리해 수정된 실패 건만 재처리하도록 설계했습니다.

만든 것

  • API·ERP·파일 공통 입력 계약
  • 정규화·계정 매핑·행 단위 검증
  • 멱등 처리와 부분 실패 로그
  • 수동 재처리와 합계·체크섬 교차검증

확인한 것

공개 사이트에서 데모와 사례 페이지를 볼 수 있으며, 샘플 산출 파일을 내려받을 수 있습니다.

  1. 확인됨

    정상·실패 분리

    샘플 3건 중 정상 2건을 보존하고 잘못된 계정 매핑 1건을 재처리 가능한 실패로 분리하는 테스트를 통과했습니다.

  2. 확인됨

    중복 방지

    이미 처리한 외부 ID를 다시 입력했을 때 새 처리 건을 만들지 않는 멱등성 테스트를 통과했습니다.

  3. 확인됨

    Looker Studio CSV 출력

    처리된 건을 헤더가 고정된 CSV(BOM 無)로 내보내는 toLookerCsv 출력을 테스트로 통과했습니다.

  4. 확인됨

    클라이언트용 실패 설명

    실패마다 failureId·코드·설명·재처리 여부를 한 줄로 보여주는 explainFailures 출력을 테스트로 통과했습니다.

  5. 확인 중

    고객 성과

    실제 고객의 처리 시간·오류율·비용 개선은 아직 측정하지 않았습니다.

화면

쓰기 전에 알아 둘 점

가상의 전표 ID·계정 코드·금액만 사용합니다. 고객명, 연락처, 공고 번호, 원장 경로는 사례와 데모에 포함하지 않습니다.

  • 메모리 기반의 작은 샘플 데모이며 운영 데이터베이스와 큐의 내구성을 증명하지 않습니다.
  • 특정 ERP·회계 포맷의 실제 인증, 필드 매핑, 처리량은 유료 진단 뒤 별도 검증합니다.
  • 공개 데모는 가상 데이터만 사용하며 실제 고객 시스템 연결을 포함하지 않습니다.
