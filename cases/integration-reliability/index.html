Integration Reliability Web Service

ERP·API·파일 연동에서 실패 행이 섞이면, 어떤 건을 그냥 다시 돌리면 되고 어떤 건은 코드를 고쳐야 하는지가 시스템마다 달라 사람이 매번 판단해야 하는 문제

지금 상태
공개 데모에서 직접 올린 파일로 확인 가능내 연동 시스템의 실패 로그 CSV를 올리면 어떤 건이 재처리 가능하고 어떤 건은 데이터를 고쳐야 하는지 브라우저 안에서 분류합니다. 범용 규칙에 없는 코드는 ‘확인 필요’로 정직하게 분리합니다. 파일은 서버로 전송되지 않습니다.
단계
브라우저 직접 파일 실행 기능 반영 · 공개 데모에서 확인
직접 확인
내 실패 로그로 바로 돌려보기 ↗

누구를 위해, 어떻게

이 제품을 찾는 사람
엑셀·ERP·외부 API 사이에서 반복 업로드와 재처리를 운영하는 개발·운영 팀
처음부터 신경 쓴 점
실제 고객 시스템 접속 없이 내 파일로 검증해야 하고, 각 시스템의 코드 체계에 맞춰 규칙을 하드코딩하지 않으며, 샘플 결과를 고객 성과로 말하지 않습니다.
고른 해결 방법
업로드된 실패 로그를 브라우저 안에서만 분류합니다. 타임아웃·5xx·429 같은 일시적 패턴은 재처리 후보로, invalid·not_found·4xx 같은 영구 패턴은 재처리 불가로, 범용 어휘에 없는 코드는 ‘확인 필요’로 분리해 사용자가 내 코드 기준으로 최종 판단합니다.

만든 것

  • 브라우저 전용 실패 로그 분류기(서버 전송 0)
  • 일시적/영구/확인 필요 3분류(범용 어휘)
  • 외부 ID 멱등 키와 중복 건 자동 제외
  • 행별 분류 CSV 다운로드(코드·분류·사유)

확인한 것

공개 사이트에서 데모를 열고, 내 실패 로그를 올려 돌려본 뒤 행별 분류 CSV를 내려받을 수 있습니다.

  1. 확인됨

    직접 파일 왕복

    샘플 입력 CSV 8행을 올리면 6건 분류(재처리 가능 3 · 불가 2 · 확인 1), 중복 1건 제외, 코드 누락 1건 분리되는 것을 테스트로 통과했습니다.

  2. 확인됨

    토큰 경계 매칭

    14045 같은 코드가 404로 잘못 매칭되지 않고, HTTP/429는 재처리 가능한지로 분류하는 것을 테스트로 통과했습니다.

  3. 확인됨

    결정적 분류

    같은 파일을 두 번 올리면 분류 결과가 완전히 동일한 것을 테스트로 통과했습니다.

  4. 확인 중

    고객 성과

    실제 고객의 재처리 판단 시간·오류율 개선은 아직 측정하지 않았습니다.

화면

쓰기 전에 알아 둘 점

올린 CSV는 이 브라우저 안에서만 처리되어 서버로 전송되지 않습니다. 공개 데모의 샘플은 외부 ID·코드·사유만 사용하는 가상 데이터입니다.

  • 분류는 범용 어휘(타임아웃·5xx·429 / invalid·not_found·4xx 등) 기반의 휴리스틱이며, 내 시스템의 코드 매뉴얼에 맞춘 분류는 사용자가 확인한 뒤 확정합니다.
  • 브라우저에서 파일 하나를 올리는 검증 도구이며, 실제 연동 시스템 접속·웹훅·운영 처리량은 검증하지 않았습니다.
  • ‘확인 필요’로 분리된 코드는 이 도구가 판단한 것이 아니라 사람 판단을 요청하는 표시입니다.
