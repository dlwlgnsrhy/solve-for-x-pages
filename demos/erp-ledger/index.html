검증 가능한 샘플 데모

ERP Ledger Kit

전표 자동화의 핵심은 숫자가 아니라 신뢰입니다. 3개 회계 시스템의 전표를 하나의 장부로 정규화하고, 차변·대변이 균형을 맞추는지, 이미 넣은 전표가 다시 들어가지 않는지를 샘플 데이터로 확인합니다.

1. 3개 소스의 전표 5건 입력

영림원·아마란스·SAP의 전표가 공통 계약(소스·전표번호·계정·차변·대변)으로 들어옵니다. 마지막 1건은 첫 전표의 번호가 다시 온 경우입니다.

입력 전표 (샘플 5건)
소스전표 번호계정차변대변
영림원YR:2026-0001매출-영림원2,000,000원—
아마란스AM:2026-0001매출-아마란스—1,000,000원
SAPS:2026-0001매출-SAP1,000,000원—
아마란스AM:2026-0002매출-아마란스—2,000,000원

2. 차변·대변 균형 검증

수락된 4건의 합을 다시 계산해 비교합니다 — 차변 3,000,000원 = 대변 3,000,000원 이므로 이 장부는 균형(balanced) 상태입니다.

3. 중복 전표 멱등 필터

이미 처리한 YR:2026-0001가 다시 들어오자 새 장부 행을 만들지 않고 실패 로그에 남겼습니다 — 다시 업로드해도 숫자가 두 번 들어가지 않습니다.

4. 재처리 시 멱등성

실패 기록 1건을 그대로 다시 보내면, 이미 처리된 전표이므로 새 반영 0건, 건너뜀 YR:2026-0001 로 SUCCEEDED — 결과가 번복되지 않습니다.

이 데모가 증명하지 않는 것

샘플 데이터와 메모리 기반 처리로 전표 정규화·균형·멱등 구조를 검증한 기술 데모입니다. 특정 ERP의 실데이터 연결, 인증, 처리량, 실제 회계 시스템과의 정합은 아직 검증하지 않았습니다.
