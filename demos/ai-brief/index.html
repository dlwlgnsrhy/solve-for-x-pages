검증 가능한 샘플 데모 (가상 데이터) · LLM 無

AI Brief Kit

제안 쓰는 시간을 줄이는 가장 안전한 방법부터입니다. 위시켓 건의 제목과 금액만으로 분류·수수료 구간·접근법 3항목·1페이지 초안을 만드는 프로토타입 — LLM 없이, 같은 입력이면 항상 같은 출력을 내는 결정적 규칙 기반입니다.

이 킷이 해결하는 문제

위시켓·크몽 건마다 1~2시간씩 제안서를 쓰는 일, 그리고 수수료 20% 건은 아예 안 쓰는 게 이득인 소모 경쟁을 구분하지 못하는 문제입니다. 이 킷은 제목과 금액으로 분류·수수료 구간을 정하고 1페이지 제안 초안을 만듭니다 — LLM 없이, 결정적 규칙으로.

이 예시가 뭘 보여줍니까

100% 가상 데이터입니다. 가상의 건 3건(게시액 15,000,000원 / 7,000,000원 / 3,000,000원) — 300만 원 건은 수수료 20% 구간에 의도적으로 들어 있습니다. 아래는 분류 결과, 접근법 3항목 초안, 그리고 NO-BID 경고가 나오는 과정입니다.

1. 위시켓 건 3건 입력

제목과 게시액만 넣습니다. 제목에서 카테고리(우선순위 ERP > 연동 > BI > EC > AI)를 분류하고, 금액으로 수수료 구간을 정합니다.

생성된 제안 초안 (샘플 3건)
제목분류게시액수수료 구간
온라인 스토어 주문 데이터 연동 개발연동15,000,000원10%
AI 챗봇 서비스 개발AI7,000,000원15%
대시보드 리포트 개발BI3,000,000원20%

2. 접근법 3항목 + 1페이지 초안

첫 건(연동)의 초안을 그대로 보여줍니다 — 분류, 구간, 접근법 3항목이 한 장에 들어옵니다.

sample-brief.md다운로드
# [연동] 온라인 스토어 주문 데이터 연동 개발 — 제안 초안

- **분류:** 연동 · **게시액:** 15,000,000원 · **수수료 구간:** 10%

## 접근법 (3항목)
1. API·ERP·파일 사이를 공통 입력 계약(정규화·매핑·검증)으로 연결해, 어느 쪽이 늦게 도착해도 중복 없이 하나씩만 반영되도록 설계합니다.
2. 일부 행이 실패해도 정상 행을 보존하고, 실패 행만 원인이 기록된 로그로 분리해 수정된 건만 재처리하는 복구 흐름을 제공합니다.
3. 매 실행마다 합계와 체크섬을 교차 검증해, 클라이언트가 '몇 건이 처리됐고 왜 실패했는지'를 화면으로 확인할 수 있게 합니다.

3. NO-BID 경고 (20% 구간)

세 번째 건(300만 원, 수수료 20% 구간)은 팀의 수락 경계에 걸려 초안에 경고 줄이 함께 나옵니다 — 소모 경쟁에 돈이 들기 전에 거르는 것도 도구의 역할입니다.

> **NO-BID 경고:** 500만 원 미만(수수료 20% 구간) 제안은 팀의 수락 경계상 권장하지 않습니다.

내 제안 리스트로 확인

내가 쓴 제안·과제 CSV를 올려보세요 — 제안 제목·게시액 열이 있으면 됩니다.LLM을 쓰지 않습니다: 팀의 키워드 규칙(ERP·연동·BI·EC·AI)과 수수료 구간(10/15/20%)만으로 분류하고, 500만 원 미만은 NO-BID 경고를 붙입니다. 같은 파일이면 언제나 같은 결과입니다.샘플 입력 CSV를 내려받아 그대로 돌려도 됩니다.

내 파일로 바로 돌려보기

파일이 서버로 전송되지 않습니다 — 모든 처리가 이 브라우저 안에서 끝납니다.

CSV 파일을 여기에 놓거나

이것이 주는 가치

  • 건당 1~2시간 → 1페이지 초안 자동 생성 — 쓰기 시작하는 시간이 아니라 검토하는 시간에서 시작합니다.
  • 20% 수수료 건은 NO-BID로 선 긋기 — 소모 경쟁에 돈을 쓰기 전에 거릅니다.
  • 동일 입력 = 동일 출력 — 결정적이고 감사 가능한 프로토타입입니다.

이 데모가 증명하지 않는 것

키워드·구간 규칙 기반 프로토타입입니다. LLM 기반 자연어 제안 생성, 실제 위시켓 API 연결, 제안 채택률은 검증하지 않았고, LLM 도입 여부는 별도 사람 결정 사항입니다.
