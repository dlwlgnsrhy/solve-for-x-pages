검증 가능한 샘플 데모 (가상 데이터)

Cafe24 Sync Kit

쇼핑몰 주문 동기화에서 무서운 건 한 건의 실패가 아니라 그 실패가 전체를 막는 것입니다. 10건 중 1건이 상태값 오류여도 9건은 그대로 반영되고, 실패한 1건만 로그로 남는 구조를 샘플로 확인합니다 — 그리고 내 쇼핑몰의 주문 CSV를 직접 올려서도 확인합니다.

이 킷이 해결하는 문제

쇼핑몰 주문을 다른 시스템에 넘길 때 원시 상태코드(20/21/22/50)를 사람이 번역해야 하고, 1건의 상태값 오류가 전체 동기화를 멈추거나 주문이 두 번 기록되는 문제입니다. 이 킷은 상태값을 의미 있는 4상태로 매핑하고, 1건 실패해도 나머지를 보존하며, 재동기화에서 중복을 거릅니다.

이 예시가 뭘 보여줍니까

100% 가상 데이터입니다. 가상의 주문 10건 — 그중 1건은 상태값 99(미지정)가 의도적으로 들어 있습니다. 아래는 10건 동기화, 1건 부분 실패, 재전송 시 멱등 처리의 전체 과정입니다. 모든 금액은 샘플 데이터입니다.

1. 상태값 매핑과 10건 동기화

카페24의 원시 상태값(20/21/22/50)을 의미 있는 상태로 매핑해 10건을 동기화했습니다. 9건 반영, 1건 실패 — 실패 건은 C24-1005(상태값 99, 미지정) 하나입니다.

2. 1건 실패, 9건 보존

상태값 99는 매핑표에 없습니다. 이 건만 실패 로그에 남기고 나머지는 그대로 반영했습니다 — INVALID_STATUS: 알 수 없는 주문 상태값 99 — 매핑표를 확인해야 합니다.

3. 재동기화 시 멱등성

1001·1002가 이미 동기화된 상태에서 1001~1003이 재전송되면, C24-1001·C24-1002는 건너뛰고 C24-1003만 새 반영됩니다. 주문이 두 번 기록되는 일은 없습니다.

4. 직접 올린 파일로 확인

내 쇼핑몰·발주 시스템에서 내보낸 주문 CSV를 올려보세요 — 주문번호·상태·금액 열이 있으면 됩니다. 상태코드는 내 파일의 값 그대로 분포로 보여 주며, 상태값 누락·중복 주문·금액 오류만 거릅니다.샘플 입력 CSV를 내려받아 그대로 돌려도 됩니다.

CSV 파일을 여기에 놓거나

이것이 주는 가치

  • 1건이 깨져도 9건은 동기화됩니다 — 실패가 전체를 멈추지 않습니다.
  • 재동기화 시 중복 0 — 주문은 두 번 기록되는 일이 없습니다.
  • 상태코드는 “의미”로 번역되어 로그에 남습니다 — 사람이 코드를 번역하지 않아도 됩니다.

이 데모가 증명하지 않는 것

샘플 주문 10건으로 매핑·멱등 구조를 검증한 기술 데모입니다. 실제 카페24 스토어 연결, 웹훅, 운영 주문 처리량은 아직 검증하지 않았습니다.
